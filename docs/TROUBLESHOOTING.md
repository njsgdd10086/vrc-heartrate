# 常见问题

## 摄像头相关

### 摄像头下拉框是空的 / 一直转圈

**原因**：程序需要先枚举设备（逐个打开测试能否出帧），这一步要几秒。

**如果某个摄像头正被其他程序占用**，枚举会为该索引等待驱动超时。
程序对此有保护：单次探测最多 4 秒、整轮最多 25 秒，超时就跳过该索引
（日志里会看到 `摄像头 #N 探测超时`）。

代价是**被占用的那颗摄像头可能不会出现在列表里**。想让它出现：

1. 先关掉占用它的程序（面补 / 相机 App / 浏览器 / OBS）
2. 回到界面点「刷新列表」

**排查步骤**：
1. 若日志里出现 `人脸检测器初始化失败`，说明 OpenCV 读不了模型路径
   （通常是路径含中文，见 [BUILD.md](BUILD.md) 坑 2 —— 正式版已自动规避）
2. 点「刷新列表」重试

### 点「开始」后没有画面

看状态栏文字，它已区分为几种情况：

| 状态栏提示 | 含义 | 处理 |
|---|---|---|
| `正在打开摄像头...` | 设备忙，还在尝试 | 等几秒；若一直如此，见下一条 |
| `摄像头已打开但读不到帧` | 设备被独占 | 关掉相机 App / 浏览器 / OBS / 面补 |
| `未检测到人脸` | 画面正常但没人脸 | 正对镜头、改善光照 |
| `正在测量...` | 正常，在积累数据 | 等 10~15 秒 |

### 摄像头被别人占用了

USB 摄像头通常**只允许一个程序打开**。两条路：

1. **各用一颗摄像头** —— 如果你有两颗（外接 + 内置），让两边各用一颗
2. **启用虚拟摄像头** —— 见 README 的「方案 B」

### 下拉框里哪些设备不能用

- 标了 `[红外]` 的：画面几乎无色彩，rPPG 依赖颜色变化，**不可用**
- 标了 `[虚拟·xxx]` 的：虚拟摄像头。如果它是别的程序（OBS/Warudo）输出的，
  只有当那个程序在运行时才有画面

## 心率相关

### 一直不出心率

需要同时满足：

- 画面里有清晰的人脸（看画面右上角，状态栏应显示 `人脸可见`）
- 信号强度达到门限（默认 0.30）。看状态栏的 `信号强度`
- 累积约 10~15 秒数据

信号强度低是最常见原因，改善方式：

1. **光照** —— 正面、稳定、充足。避免身后有窗户、避免屏幕亮度变化
2. **保持不动** —— 大幅度移动会毁掉信号
3. **摄像头自动曝光** —— 这是最大杀手。若摄像头支持手动曝光，去驱动设置里
   关掉自动曝光（静止墙面都不该有百分之几的亮度波动）
4. **换摄像头** —— 不同摄像头差异极大

### 心率数值一直在跳

- 调低「平滑系数」会让读数更稳（但更迟钝）
- 调高「信号门限」会过滤掉弱信号读数（但可能长时间不出数）
- 若信号强度只在 0.2~0.3 徘徊，说明这个摄像头+光照条件就是勉强够用

### 心率准不准

**请自行用参照设备核对**（手环 / 手机 / 血氧仪）。本项目无法保证精度：

- 这是**研究模型，不是医疗器械**
- 信号强度 >0.45 时可信度较高；0.30~0.45 属"可用但可能偏差"；<0.30 不输出
- 状态栏的 `两法一致 / 两法不一致` 是重要参考：两法一致时更可信

### 为什么红外摄像头不能用

rPPG 靠检测皮肤里血液带来的**颜色**微小变化（约 0.1% 量级）。
红外画面基本没有色彩信息，因此无法测。

## VRChat 相关

### Avatar 参数没反应

1. 确认 VRChat 里 **设置 → OSC → Enabled** 已打开
2. 确认 Avatar 上有一个 `float` 参数，参数名与界面里的 OSC 地址对应
   - 地址 `/avatar/parameters/VRCOSC/Heartrate/Value`
   - 对应参数名 `VRCOSC/Heartrate/Value`
3. 点「发送测试 OSC」看是否返回成功

### 聊天框不显示

1. 确认 VRChat 里 OSC 已开启
2. 先点「发送一条测试聊天框消息」确认通路
3. 发送间隔不要小于 3 秒 —— VRChat 对聊天框有频率限制，太快会被丢弃
4. 聊天框内容约 30 秒后自动消失，这是 VRChat 的行为

### 虚拟摄像头面补读不到

- **顺序**：必须先点「开始」，虚拟摄像头才存在
- 需要用 OBS 提供虚拟摄像头驱动（**OBS 本身不用运行**）
- 确认状态栏显示了设备名（如 `虚拟摄像头: OBS Virtual Camera`）
- 到面补软件里选这个设备；部分软件需要重启才能看到新设备

## 界面相关

### 双击 exe 没反应 / 界面很久不出来

正常情况下 **8 秒内**浏览器就会打开界面。

如果长时间没反应，先看日志文件（路径在启动时打印，通常是
`%USERPROFILE%\.vrc_heartrate_cam\vrc-heartrate.log`）。

常见原因是**摄像头被其他程序占用**导致初始化变慢。程序已为此加了超时保护
（单次探测 4 秒、整轮 25 秒，超时跳过），所以最多等约 25 秒就会出界面。
若超过这个时间仍无反应，请把日志附到 Issue。

### 状态栏一直显示「正在打开摄像头……或设备被其他程序占用」

这就是字面意思：设备被独占了。两条路：

1. **换一颗摄像头**（下拉框里选另一个）
2. **启用虚拟摄像头**，让占用方改用虚拟摄像头 —— 见 README 的「方案 B」

### 界面卡住 / 数字不再变化

程序有多层自愈（采集异常自动重开、轮询异常自动跳过），正常不该卡死。
若确实卡住：

1. 看日志有没有 `采集异常已自动恢复` 或 `刷新界面失败（已忽略）`
2. 关掉重开
3. 把日志发到 Issues

### 画面帧率低 / 预览卡

程序会自动在 DSHOW 与 MSMF 之间选读帧更快的后端，并打印实测帧率
（日志里能看到 `摄像头 #0 打开成功: MSMF 640x480，实测 28.2 fps`）。

`cap.read()` 占整条流水线约 85% 的时间，所以：

1. **换一颗摄像头试试** —— 不同摄像头差异极大。实测同一台机器上，
   外接 USB 摄像头比笔记本内置的快一倍（30 fps vs 15 fps）
2. **降低分辨率** —— 用 `--size 640x480`（默认就会优先试这个）
3. **关掉其他占用摄像头的程序** —— 被抢占时读帧会变慢甚至失败
4. 预览约 15 fps 是设计值（传输要 base64 编码，成本不低），
   对测心率**没有影响** —— 心率估计靠的是时间轴，不是帧率

如果日志里那行显示 `实测 N fps` 而 N < 12，程序会额外警告一次。

### 端口被占用

程序会自动顺延到下一个可用端口，并在界面/日志中提示实际地址。
也可以手动指定：`--port 7900`。

## 想反馈问题

请附上：

1. 用 `启动.bat` 运行后的**完整日志**
2. 状态栏截图（含信号强度与 fps）
3. 摄像头型号、光照情况
4. 用参照设备测到的真实心率（如果方便）

这些信息能极大缩短排查时间 —— 尤其是**信号强度**，它直接决定问题
出在信号采集还是算法。
